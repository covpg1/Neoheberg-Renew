# Neoheberg 自动续期（GitHub Actions）

用 GitHub Actions 定时登录 [Neoheberg](https://dash.neoheberg.fr/login) 面板：剩余天数不足时自动续期，并定期检查服务器状态，已停止就自动开机。单账号、单代理，配置简单。

> 本项目与 Neoheberg 官方无关。登录与续期流程参考了公开仓库 [yousb66/neoheberg-renew](https://github.com/yousb66/neoheberg-renew) 的实现。使用前请确认符合 Neoheberg 的服务条款，风险自负。

## 功能

- 无头浏览器登录（两步式表单 + Cap.js 验证码），读取到期日，剩余天数 ≤ 阈值（默认 14 天）才续期
- 续期后以面板上的到期日是否真的延长来判断成败
- **服务器状态检查**：独立的定时任务（默认每 6 小时）检查容器是否在运行，已停止则自动开机并确认真的运行起来
- 可选代理：节点分享链接（经 sing-box）或现成的代理地址
- 可选 Telegram 推送
- 仓库保活：每次续期运行更新 `last_check.txt`，避免 GitHub 60 天无活动后停用定时任务

## 文件说明

```
.
├── renew.py                      # 主脚本：登录、续期、状态检查与开机、TG 推送
├── setup_proxy.py                # 把节点分享链接转成本地 SOCKS5 代理（sing-box）
├── last_check.txt                # 自动生成：上次检测时间（保活用）
└── .github/workflows/
    ├── renew.yml                 # 每 29 天续期检查（同时顺带检查一次容器状态）
    └── status.yml                # 每 6 小时检查容器状态，停止则自动开机（已停用）
```

## 快速开始

1. 新建一个仓库（**建议私有**，原因见[安全建议](#安全建议)），把上面的文件放进去。
2. 进入 **Settings → Actions → General → Workflow permissions**，选择 **Read and write permissions**（保活要往仓库提交文件）。
3. 进入 **Settings → Secrets and variables → Actions**，添加 Secrets（见下表，最少需要前三项）。
4. 打开 **Actions** 页面，选择 `Neoheberg Renew` → **Run workflow**，手动运行一次，看日志确认成功。
5. 之后续期检查每 29 天自动运行一次，状态检查已停用。

### Secrets

| 名称 | 必填 | 说明 |
|---|---|---|
| `NEO_USER` | 是 | 账号（邮箱或用户名） |
| `NEO_PASSWORD` | 是 | 密码 |
| `NEO_VMID` | 是 | 服务实例 ID（纯数字，不要加引号或前缀）。登录面板后可在服务列表或服务详情页的 URL 中找到，具体位置以面板为准 |
| `NODE_LINK` | 可选 | 代理：节点分享链接，经 sing-box 转成本地 SOCKS5 |
| `PROXY_SERVER` | 可选 | 代理：现成的代理地址。与 `NODE_LINK` 二选一，都配时 `NODE_LINK` 优先 |
| `TG_BOT_TOKEN` / `TG_CHAT_ID` | 可选 | Telegram 推送 |

### Variables（可选，留空用默认值）

| 名称 | 默认 | 说明 |
|---|---|---|
| `RENEW_DAYS` | `14` | 剩余天数小于等于该值才续期 |
| `START_WAIT` | `90` | 下发开机指令后，最多等多少秒确认容器运行起来 |
| `TG_NOTIFY` | `always` | 续期任务的推送策略：`always` 每次都推送；`change` 续期、自动开机或失败时才推送；`fail` 仅失败时推送 |
| `STATUS_TG_NOTIFY` | `change` | 状态检查任务的推送策略，取值同上 |

## 代理

GitHub Actions 的机房 IP 信誉较低，容易被 Cloudflare 的托管质询（Turnstile）拦截，表现为登录页变成「Vérification de sécurité en cours」。解决办法是使用干净的固定出口 IP（住宅 / 家宽 IP 最稳）。不配置代理则直连。

| 方式 | 配置 | 说明 |
|---|---|---|
| 节点分享链接 | Secret `NODE_LINK` | 支持 `vless` `vmess` `trojan` `ss` `hysteria2`（`hy2`）`tuic` `socks5` `http`。由 sing-box 在本机 `127.0.0.1:1080` 开一个 SOCKS5 入口 |
| 现成的代理 | Secret `PROXY_SERVER` | 如 `http://user:pass@1.2.3.4:8080`、`socks5://5.6.7.8:1080` |

- 只使用一个代理：多行时只取第一个有效行。
- Chromium 不支持带账号密码的 SOCKS5。有认证的请用 HTTP 代理，或改用 `NODE_LINK`。
- **绝不悄悄直连**：配置了代理但它不可用（或 `NODE_LINK` 启动失败）时，本次任务会直接取消并通知你，而不是改用直连。直连在机房 IP 上几乎必然被拦截，还会让 IP 更脏。
- 节点启动后会先做一次连通性自检，日志里只显示脱敏后的出口 IP，不会出现节点的完整地址。

## 服务器状态检查

`status.yml` 是独立于续期的定时任务：登录后检查容器状态，**已停止就自动开机，并等待确认它真的运行起来**。它只检查状态，不续期（续期由 `renew.yml` 每 29 天执行；续期任务结束时也会顺带检查一次容器）。

> 注：该工作流目前已在 Actions 里停用，不再定时运行。

| 容器状态 | 处理 | 结果 |
|---|---|---|
| 运行中 | 不做任何操作 | ✔️ 运行中（剩余 N 天） |
| 已停止（`stopped` / `halted` / `shutdown` / `shutoff` / `off` 等） | 下发开机指令，每 5 秒查一次状态，最多等 `START_WAIT` 秒 | 🔄 已自动开机；超时仍未运行或请求被拒则 ❌ 开机失败 |
| 其他状态（如 `paused`） | **不自动处理**，避免乱发指令 | ❌ 状态异常，推送通知 |
| 查询状态本身失败（接口变了、网络问题） | 不发开机指令 | ❌ 无法获取容器状态，推送通知 |

要点：

- **频率**：默认每 6 小时一次（UTC 00:17 / 06:17 / 12:17 / 18:17），服务器最多停机一个检查周期。在 `status.yml` 里改 `cron`，例如每 12 小时 `"17 */12 * * *"`，每天一次 `"17 3 * * *"`。
- **推送**：状态检查很频繁，默认只在「有变化」时推送（自动开机了、出错了），正常时不打扰你。想每次都推送或只在失败时推送，设置 Variable `STATUS_TG_NOTIFY` 为 `always` 或 `fail`。
- **排队**：续期和状态检查共用同一个并发组，不会同时登录（同时登录容易触发站点限流），后到的会排队等待。
- **代价**：每次检查都要登录（含约十几秒的验证码）。每 6 小时检查一次，一天登录 4 次。担心被站点限流时，把频率调低。
- 手动触发：**Actions → Neoheberg Status → Run workflow**。

## Telegram 推送

1. 在 [@BotFather](https://t.me/BotFather) 创建机器人，拿到 Token，填入 Secret `TG_BOT_TOKEN`。
2. **先给机器人发一条消息**，否则它无法主动联系你。
3. 获取你的 Chat ID（如通过 [@userinfobot](https://t.me/userinfobot)），填入 Secret `TG_CHAT_ID`。
4. 需要调整推送频率时，设置 Variable `TG_NOTIFY` / `STATUS_TG_NOTIFY`。

推送内容：结果（续期成功 / 无需续期 / 自动开机 / 失败原因）和运行日志链接，**不含账号、密码、实例 ID、代理地址和 IP**。workflow 在启动阶段（如依赖安装）就失败时，也会有一条兜底提醒。推送本身失败只记一条警告，不影响任务结果。

## 运行时间与手动触发

- 续期检查：每天 UTC 02:00 触发，满 29 天才真检查（门禁在 `renew.yml` 里，cron 本身写不出 29 天间隔）。每次只检测，剩余天数大于阈值就不续期。
- 状态检查：已停用，见上一节。
- 手动：**Actions → Neoheberg Renew（或 Neoheberg Status）→ Run workflow**。续期任务里勾选 `force_renew` 会忽略剩余天数，强制续期一次。
- 阈值与频率的关系：续期检查每 29 天一次、窗口 14 天，只有当 29 天的倍数落在到期前 14 天内时才会续上（31 天周期可兜住）；换机器后以实测周期为准，周期不对要改间隔或窗口。

## 仓库保活

GitHub 会在公开仓库 60 天没有活动后自动停用定时任务。每次真检查结束后（无论成功失败），workflow 会把检测时间写入 `last_check.txt` 并提交，保证仓库每 29 天都有新提交，定时任务不会被停用（门禁跳过的运行不提交）。只提交这一个文件，不会带上调试截图。

```
last_check: 2026-10-19 02:00:13 UTC
status: success
run: https://github.com/<用户名>/<仓库>/actions/runs/<编号>
```

前提是第 2 步的 **Read and write permissions** 已开启，否则推送会被拒绝（日志里会有提示）。建议第一个月后检查一次 Actions 页面，确认定时任务没有被停用。

## 日志说明与常见问题

| 日志 | 原因与处理 |
|---|---|
| `缺少配置: …` | 没有设置 `NEO_USER` / `NEO_PASSWORD` / `NEO_VMID` 中的某几项 |
| `检测到 Cloudflare 质询页` / `被 Cloudflare 托管质询拦截` | 出口 IP 信誉低。配置 `NODE_LINK` / `PROXY_SERVER`，换一个更干净的节点，或改用自托管 runner |
| `站点提示: Identifiants invalides` | 账号或密码错误。Discord 注册的账号默认没有密码，需先用「Mot de passe oublié ?」设置。**脚本遇到该提示只会试一次**，反复输错可能被站点限流甚至锁号 |
| `密码=N位` | 脚本实际读到的密码长度，可与真实密码核对有没有多带引号、空格 |
| `代理不可用，本次取消（不会直连）` | 配置的代理连不上，请检查或更换 |
| `配置了代理（NODE_LINK）但启动失败` | 节点链接无效或节点已失效（日志里有解析/连通性检查的具体信息） |
| `登录表单未渲染` | 站点偶尔返回残缺页面，稍后手动重跑 |
| `验证码求解超时` | 网络或代理过慢，重跑 |
| `未取到 CSRF token` | 登录后页面结构异常，查看 Artifacts 里的截图 |
| `续期未生效（到期日仍为 …）` | 续期请求发出了，但面板上的到期日没有延长。检查 `NEO_VMID` 是否正确，或是否还没到可续期的时间 |
| `续期结果无法确认` | 读不到续期后的到期日，站点也没给出明确结果。以面板上的实际到期日为准 |
| `容器已停止，正在开机 …` / `容器已启动（状态: running）` | 检测到容器停止并已自动开机成功 |
| `开机请求被拒绝: HTTP …` / `N 秒内状态仍为 …` | 开机指令没有生效，请到面板手动查看；可调大 `START_WAIT` |
| `容器状态「…」不是已知的运行/停止状态` | 遇到脚本不认识的状态（如 paused），不会自动处理，请手动检查 |
| `查询容器状态失败` | 状态接口异常，可能是站点改版；查看 Artifacts 或面板 |
| `Telegram 推送失败: HTTP 401` / `HTTP 400` | 分别是 Token 无效 / Chat ID 无效或没给机器人发过消息 |
| `push 失败（已忽略）` | 没有开启 Read and write permissions |

运行失败时，Actions 页面底部的 **Artifacts → debug** 里有截图和页面 HTML，可用于排查。

## 安全建议

- **使用私有仓库。** 日志里账号和密码会被屏蔽，但失败时上传的截图是登录页原貌，可能带有账号信息。
- 所有凭据只放在 Secrets 里，不要写进代码或提交到仓库。
- 站点对登录有限流，不要频繁手动触发，更不要反复用错误密码运行。
- 脚本不会在日志里输出密码，只输出位数。

## 工作原理

1. 打开登录页，先填账号并点「Continuer」，等密码框出现。
2. 触发 Cap.js 验证码（浏览器内工作量证明，约十几秒），等待 `cap-token` 生成。
3. 提交登录，成功后在已登录页面内用 `fetch` 读取到期日和 CSRF token。
4. 续期任务：剩余天数不足时向 `/services/renew` 提交续期，然后重新读取面板上的到期日，**以到期日是否真的延长来判断成败**（续期响应里的提示文案不可靠，只在读不到到期日时作为参考）；再查询容器状态，已停止则下发开机并轮询确认。状态检查任务（`MODE=status`）只做最后这一步，不续期。
5. 推送 Telegram，并（续期任务）更新 `last_check.txt`。

## 已知限制

- 登录、续期、读取容器状态已在真实账号上跑通（日志里出现过 `容器状态: running`）。**「容器已停止时自动开机」还没有遇到过真实的停止场景，没有实测过**，开机接口基于公开仓库的实现编写；第一次真正触发时请留意日志和 Telegram。
- 站点改版（表单字段、接口路径、验证码方案）后脚本可能失效，需要按日志和截图调整。
- 没有实现自动点击 Cloudflare Turnstile，被拦截时的办法是更换出口 IP。
- 保活的有效性依赖 GitHub 对机器人提交的处理，建议偶尔确认定时任务仍在运行。

## 从多账号版本迁移

如果之前用过多账号版本，注意这些变化：

- 只读取 `NEO_USER` / `NEO_PASSWORD` / `NEO_VMID` 三个 Secret，**不再读取 `NEO_ACCOUNTS`**。
- 不再有账号专用代理（`proxy` 字段）、代理降级和账号间隔（`ACCOUNT_GAP`）。
- `NODE_LINK` / `PROXY_SERVER` 只取第一行，且只作为一个代理使用。
- 代理启动失败的标记变量改名为 `PROXY_FAILED`（脚本仍兼容旧名 `GLOBAL_PROXY_FAILED`）。
